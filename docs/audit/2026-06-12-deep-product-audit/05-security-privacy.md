# Фаза 6. Security, privacy, abuse resistance

Дата: 2026-06-12  
Статус: обязательные проверки зелёные, детерминированных P0/P1 security/privacy дефектов не найдено.

## Итог

Продукт нельзя честно назвать "лучшим" в security/privacy смысле уже сегодня, но базовая защитная архитектура сильная: consent/subscription gates, Mini App HMAC, webhook secret, дедупликация апдейтов, user-scoped report/chat доступ, SSRF-защита загрузки изображений, retention/delete-me, безопасные промпты и deterministic grounding уже присутствуют.

Главные оставшиеся риски не выглядят как немедленная эксплуатация. Это gaps уровня "best-in-class before scale": долговременный audit trail для OSINT lawful basis, отдельный тестовый контракт на мощные admin-команды и полный privacy-delete сценарий с артефактами/платёжными payload/raw-полями/хранилищем.

## Abuse / Privacy Boundary Review

- Harassment/doxing/privacy-bypass: заблокировано на уровне UI copy, report prompt, chat prompt и OSINT prompt. Прямые инструкции к преследованию, doxing, social engineering, privacy bypass запрещены в `src/prompts/report.standard.v1.ts:13`, `src/prompts/chat.report.v1.ts:5`, `src/prompts/report.osint-compliance.v1.ts:10`.
- Sensitive inference: `HARD_RULES` запрещает relationship/marital/partner/identity/employment/income/wealth/health/political/religious/sexual claims; deterministic grounding ловит fabricated sources и forbidden inference before repair.
- Photo search: фича выключена по умолчанию, требует подтверждения права на фото, ограничивает MIME/размер и использует idempotency key. Для лучшего класса нужен отдельный policy/runbook по обработке биометрических запросов и retention/consent audit для FaceCheck, если фича будет включаться.
- HR: фича выключена по умолчанию; prompt явно не является hiring decision/background check и запрещает protected traits. До production-включения нужна юридическая review локального рынка, потому что HR-анализ публичных профилей может быть регулируемым процессом.
- OSINT: фича выключена по умолчанию и доступна только compliance/admin. До широкого включения главный blocker не кодовый gate, а auditability lawful basis и операционная политика допустимых use cases.

## Вывод по фазе

Security/privacy фундамент хороший и существенно выше уровня "быстро собранный Telegram bot": опасные действия gated, внешние входы валидируются, private network SSRF закрыт, отчёты scoped по userId, deletion/retention реализованы. Но "лучшим продуктом" его можно будет назвать только после усиления audit trail, privacy-delete контракта и admin-command regression tests.
